# Kenglish - Nhật ký phát triển

## Quản lý và xóa bộ từ

### 1. Chức năng đã hoàn thành
- Xóa bộ từ ở màn Bộ từ.
- Xóa bộ từ bên trong Folder.
- Menu tùy chọn custom khi nhấn dấu ba chấm.
- Kết nối API DELETE với backend.
- Xóa dữ liệu thật trong MySQL.
- Tự động xóa các từ vựng thuộc bộ từ bằng ON DELETE CASCADE.
- Cập nhật RecyclerView sau khi xóa.
- Cập nhật trạng thái Folder trống.
- Đồng bộ lại số lượng bộ từ của Folder khi quay về màn Bộ từ.

### 2. Luồng xử lý xóa bộ từ
UI → Adapter → Callback → Fragment → Retrofit → API → MySQL → Response → cập nhật UI

### 3. Các xử lý code nổi bật

#### Adapter không trực tiếp gọi API
Adapter chỉ phát sự kiện:
`listener.onXoaBoTu(boTu)`

Fragment chịu trách nhiệm gọi API và xử lý dữ liệu.

Ý nghĩa:
- Tách phần hiển thị và xử lý nghiệp vụ.
- Adapter dễ tái sử dụng.
- Giảm phụ thuộc giữa RecyclerView và tầng API.

#### Xóa quan hệ bằng ON DELETE CASCADE
Khi xóa `bo_tu`, các bản ghi `tu_vung` có `bo_tu_id`
tương ứng được MySQL tự động xóa.

#### Chỉ cập nhật UI sau khi server xác nhận thành công
Không xóa card trước khi nhận response thành công,
tránh trường hợp UI báo đã xóa nhưng database vẫn còn dữ liệu.

#### Xóa theo ID thay vì giữ position RecyclerView
Sau các thao tác tìm kiếm/thay đổi danh sách, position có thể thay đổi.
Ứng dụng tìm lại phần tử theo ID trước khi xóa.

#### Duy trì hai danh sách trong ChiTietFolder
- `danhSachBoTu`: dữ liệu gốc.
- `danhSachHienThi`: dữ liệu đang được lọc/hiển thị.

Khi xóa phải cập nhật cả hai để bộ từ đã xóa không xuất hiện lại
sau khi tìm kiếm.

#### Đồng bộ lại dữ liệu khi quay về màn Bộ từ
`onResume()` gọi lại `layDuLieuBoTu()` để lấy trạng thái mới nhất
từ backend.

Nhờ đó số lượng bộ từ của Folder không phụ thuộc vào dữ liệu
đã cache trước khi mở ChiTietFolder.
